## 背景与问题

### 问题陈述

开发者在使用多个 AI API Provider（OpenAI、DeepSeek、Claude 等）时面临以下痛点：

1. **Token 用量不透明**：无法准确知道每次 API 调用消耗了多少 token，只能依赖 provider 返回的计数，无法验证其准确性
2. **成本失控**：多个项目、多个 provider 的 API 费用分散，缺乏统一的审计和监控
3. **配置繁琐**：切换 provider 需要修改代码或环境变量，效率低且容易出错
4. **无法检测异常**：当 provider 返回的 token 计数与实际不符时（计费争议），缺乏审计手段

### 为什么现在做

- AI API 调用量激增，成本控制成为开发团队的刚需
- 现有解决方案（如手动记录、简单代理）功能单一，缺乏完整的审计能力
- Tauri 2 的成熟使得构建轻量级桌面应用成为可能

### 用户画像

**主要用户**：独立开发者、小团队技术负责人
- 同时使用 2+ 个 AI API Provider
- 月 API 费用 $50-$500
- 有技术能力配置本地代理
- 关注成本优化

---

## 目标

### 产品目标

1. **提供透明的 Token 审计能力**：让用户清楚知道每次 API 调用的真实 token 消耗
2. **简化 Provider 管理**：提供统一的 Provider 配置和切换界面
3. **零配置接入**：自动改写 Claude Desktop 等客户端的配置文件，用户无需手动操作
4. **建立信任基础**：通过本地代理 + 本地存储，确保数据安全透明

### 业务目标

- 验证产品核心价值（Token 审计）是否被用户认可
- 获取第一批种子用户（目标 50 人）
- 为 v0.2 的增强审计功能收集用户反馈

## 非目标 (Non-goals)

**v0.1 明确不做的事情**：

1. ❌ **不做复杂的数据分析**：不提供趋势图、统计分析等高级功能
2. ❌ **不做多用户/团队管理**：仅支持单用户使用，不考虑权限管理
3. ❌ **不做云端同步**：所有数据本地存储，不提供云端备份
4. ❌ **不做成本优化建议**：不提供模型选择、prompt 优化等建议功能
5. ❌ **不做非 Claude 客户端的自动配置**：仅支持 Claude Desktop 的自动配置

## 用户故事

### 核心用户故事

**作为开发者**，我希望能够：

1. **管理多个 Provider**
   - 作为开发者，我希望能够添加、编辑、删除多个 AI API Provider，以便在它们之间灵活切换
   - 作为开发者，我希望能够设置某个 Provider 为"活跃"状态，以便代理服务器使用该 Provider 的配置

2. **启动本地代理**
   - 作为开发者，我希望能够一键启动本地代理服务器，以便拦截和审计我的 API 请求
   - 作为开发者，我希望代理能够自动改写 Claude Desktop 的配置文件，以便零配置接入

3. **查看 Token 用量**
   - 作为开发者，我希望能够查看每次请求的 Token 消耗（input/output），以便了解我的 API 使用情况
   - 作为开发者，我希望能够看到 Provider 声称的 Token 数与本地计算的 Token 数的对比，以便验证计费的准确性

4. **持久化存储**
   - 作为开发者，我希望所有的审计记录能够自动保存到本地数据库，以便后续查询和分析

## 功能需求

### 1. Provider 管理

**描述**：用户可以通过 UI 添加、编辑、删除、切换 AI API Provider。

**功能点**：

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 添加 Provider | 支持配置名称、API Base URL、API Key、模型列表 | P0 |
| 编辑 Provider | 修改已有 Provider 的配置 | P0 |
| 删除 Provider | 删除不需要的 Provider（需确认） | P0 |
| 切换活跃 Provider | 设置当前使用的 Provider | P0 |
| 测试连接 | 验证 API Key 和 Base URL 是否有效 | P1 |
| 自定义模型 | 支持添加不在预设列表中的模型 | P1 |

**验收标准**：
- 用户可以通过表单添加 Provider
- 切换活跃 Provider 后，代理服务器自动使用新配置
- 删除 Provider 前有确认弹窗

### 2. 代理服务器

**描述**：启动本地 HTTP 代理服务器，拦截 AI API 请求，进行 Token 计数和审计。

**功能点**：

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 启动/停止代理 | 一键启动或停止代理服务器 | P0 |
| 自动配置 Claude | 自动改写 Claude Desktop 的 settings.json | P0 |
| 透明转发 | 请求转发给上游 Provider，响应返回给客户端 | P0 |
| 端口配置 | 支持自定义代理监听端口（默认 9090） | P1 |
| 系统托盘 | 代理运行时在系统托盘显示状态 | P2 |

**验收标准**：
- 启动代理后，Claude Desktop 无需手动配置即可使用
- 代理停止后，Claude 配置自动恢复
- 支持 SSE (Server-Sent Events) 流式响应

### 3. Token 计数

**描述**：使用 tiktoken-rs 本地计算 Token 数，与 Provider 返回的值对比。

**功能点**：

| 功能 | 说明 | 优先级 |
|------|------|--------|
| Input Token 计数 | 计算请求中的 Token 数（messages + tools） | P0 |
| Output Token 计数 | 从响应中提取 Token 数 | P0 |
| 本地计算 vs 上游声明 | 对比本地计算结果与 Provider 返回的结果 | P0 |
| 支持多模型 | 支持 DeepSeek、GPT、Claude 等模型的 Tokenizer | P0 |

**验收标准**：
- Token 计数准确率 > 95%（与 Provider 返回值对比）
- 支持常见模型的 Tokenizer（tiktoken + HuggingFace tokenizers）

### 4. 审计记录

**描述**：将每次请求的审计结果存储到本地 SQLite 数据库。

**功能点**：

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 自动入库 | 每次请求自动记录到数据库 | P0 |
| 记录字段 | 时间戳、Provider、模型、Input/Output Token、差异、请求ID | P0 |
| 请求列表 | UI 展示所有审计记录 | P0 |
| 请求详情 | 点击查看单次请求的详细信息 | P1 |

**验收标准**：
- 所有请求记录完整，无丢失
- 数据库文件存储在用户可访问的位置（~/Library/Application Support/）

### 5. 前端界面

**描述**：基于 React + Tailwind 的桌面应用界面。

**功能点**：

| 功能 | 说明 | 优先级 |
|------|------|--------|
| Provider 管理页 | 列表 + 增删改查 | P0 |
| 代理控制页 | 启动/停止 + 状态展示 | P0 |
| 请求列表页 | 审计记录展示 | P0 |
| 设置页 | 端口配置、高级选项 | P1 |

**验收标准**：
- UI 响应式，适配桌面应用窗口
- 与 Tauri 后端 API 正常通信

## 非功能需求

### 性能

- 代理转发的延迟增加 < 50ms（相比于直连）
- Token 计数计算时间 < 100ms（对于 4096 tokens 以内的请求）
- 启动代理时间 < 3 秒

### 可靠性

- 代理服务器 7x24 小时稳定运行（内存泄漏 < 10MB/天）
- 数据库写入失败时有错误提示，不丢失审计数据
- Provider 配置丢失时能够从数据库恢复

### 安全性

- API Key 加密存储（使用 OS 提供的 Keychain/Keyring）
- 代理仅监听 localhost，不暴露到公网
- 本地数据库文件权限设置为仅当前用户可读写

### 兼容性

- macOS 12+（主要目标平台）
- 支持 Claude Desktop 最新版本
- 支持常见 AI API Provider（OpenAI、DeepSeek、Claude）

## 风险与缓解

### 技术风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Tauri 2 稳定性问题 | 高 | 提前做 POC，确认核心功能可行性 |
| Tokenizer 支持不全 | 中 | 优先支持主流模型，其他模型标记为"实验性" |
| SSE 流式转发复杂 | 中 | 参考开源实现，先做基础版本 |
| SQLite 并发写入 | 低 | 使用 tokio::sync::Mutex 保护数据库连接 |

### 产品风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 用户配置 Claude 失败 | 高 | 提供手动配置指南，支持导出配置 |
| API Key 安全存储 | 中 | 使用 OS Keychain，不与配置文件明文存储 |
| Provider 返回格式变化 | 中 | 抽象 Parser 层，便于适配不同格式 |

### 市场风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 竞品提前发布类似功能 | 中 | 聚焦"审计"差异化，不做通用代理 |
| 用户量增长缓慢 | 低 | v0.1 目标是验证价值，不追求大规模用户 |

## 附录

### 技术架构概览

```
Frontend (React + Tailwind)
    ↓ Tauri API
Backend (Rust + Axum)
    ↓
┌─────────────────────────────────┐
│  Proxy Server (localhost:9090) │
├─────────────────────────────────┤
│  - Request Interceptor          │
│  - Token Counter (tiktoken-rs) │
│  - Audit Logger                │
│  - SSE Stream Forwarder        │
└─────────────────────────────────┘
    ↓
Provider API (OpenAI/DeepSeek/Claude)
```

### 数据流

1. 用户启动代理 → 改写 Claude settings.json
2. Claude Desktop 发送请求 → 代理拦截
3. 代理解析请求 → 计算 Input Token
4. 代理转发请求 → Provider API
5. 代理接收响应 → 提取 Output Token
6. 代理存储审计记录 → SQLite
7. 代理返回响应 → Claude Desktop
