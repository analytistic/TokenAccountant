## 一、产品定位与核心目标

### 产品定位

TokenAccountant 是一款面向开发者和团队的 **LLM API 审计与计费工具**。作为代理层（Proxy）拦截所有 LLM API 请求，精确审计 Token 使用情况，检测报告伪造（声明 Token 与实际审计 Token 的差异）。

### 核心用户价值

1. **精确审计** — 独立于 Provider 声明，自己算一遍 Token 数
2. **差异检测** — 发现 Provider 报告的 Token 数与实际不符的情况
3. **成本透明** — 按 Provider / 模型 / 时间维度统计 Token 消耗
4. **可信度评估** — 通过历史审计数据给每个 Provider 打分

### 目标用户

- 重度使用 LLM API 的开发者
- 需要控制 AI 成本的团队 Leader
- 对 Provider 计费有疑问的技术用户

## 三、页面需求详述

---

### 页面 1：Dashboard（仪表盘）

#### 页面目的

实时展示当前 LLM 使用状况，帮助用户快速发现异常（Token 差异、可疑请求）。

#### 信息层级

```
Dashboard
├── 顶部操作栏
│   ├── 页面标题
│   ├── 刷新按钮
│   └── 设置按钮
└── 主内容区（左-右两栏布局）
    ├── 左栏（宽）
    │   ├── Token 趋势图（上）
    │   └── 近 7 日统计（下）
    └── 右栏（窄）
        ├── 今日概览（上）
        ├── Provider 可信度排名（中）
        └── 当前请求审计（下）
```

---

#### 组件 1：Token 趋势图（左栏上）

**功能描述**
实时展示当前 Session 中 Input / Cache / Output 三类 Token 的审计值与声明值趋势对比。

**需要展示的信息**

- 三条趋势线：审计值（实线，基准）、声明值（浅色/虚线）、差值区域（半透明填充）
- 分别展示 Input、Cache、Output 三个独立子图表
- 每个子图表下方显示该类的差异率（diff rate）

**交互需求**

- 图表应支持鼠标悬停显示具体数值
- 审计值作为基准，视觉上最突出
- 声明值与审计值并列对比，差异一目了然

**数据传达目标**
让用户快速判断：Provider 是否在 Token 计数上"做手脚"。

---

#### 组件 2：近 7 日 Token 统计（左栏下）

**功能描述**
以柱状图展示最近 7 天每天的总 Token 消耗（区分审计值 vs 声明值，区分 I/C/O）。

**需要展示的信息**

- X 轴：最近 7 天的日期
- Y 轴：Token 数量（建议用 K/M 单位）
- 每组柱子：Input（蓝）、Cache（橙）、Output（绿），每个颜色有"审计"和"声明"两个柱子（或叠加展示）

**交互需求**

- 鼠标悬停显示当天详细的 I/C/O 审计值和声明值
- 当前活跃 Provider 应有视觉标记

**数据传达目标**
展示时间维度上的 Token 使用趋势和差异模式。

---

#### 组件 3：今日概览（右栏上）

**功能描述**
展示今日整体审计状况的快照。

**需要展示的信息**

1. **请求次数** — 今日已处理的 API 请求总数
2. **可疑请求数** — 差异超过阈值的请求数（需要视觉警示）
3. **I/C/O token差异率**（核心）

**交互需求**

- 你可以自己设想

**数据传达目标**
一屏内传递"今日异常"的信号。

---

#### 组件 4：Provider 可信度排名（右栏中）

**功能描述**
展示所有已配置 Provider 的可信度评分排名。

**需要展示的信息**（每个 Provider 卡片）

- 排名序号（1/2/3...，用奖牌颜色区分前三名）
- Provider 名称
- url
- 可信度评分
- I/C/O 各自的平均差异率（小字，颜色编码）

**交互需求**

- 点击卡片 → 切换该 Provider 为"活跃 Provider"
- 活跃 Provider 需要有视觉强调（如左侧边框高亮）

**数据传达目标**
帮助用户快速识别"哪个 Provider 最不可信"。

---

#### 组件 5：当前请求审计（右栏下）

**功能描述**
展示**正在进行的这一条 API 请求**的审计结果（实时或最近一条）。

**需要展示的信息**

1. **审计通过指示器** — 绿色勾 + "审计通过"（或红色叉 + "审计未通过"）
2. **审计 Token ** — Input/Cache/Output token数
3. **声明 Token 条** — Input/Cache/Output token数
4. **I/C/O 差异 Token 数**

**数据传达目标**
让用户对"当前这条请求的i/c/o三种token 的审计和声明的差值了解

让用户了解i/c的比值（比值不可以用数据 设计ui表达）

---

#### 组件 6：Session 计时器（右下角）

**功能描述**
记录当前审计 Session 的持续时间。

**交互需求**

- 点击播放/暂停按钮开始/停止计时
- 计时格式：HH:MM:SS
- 按钮在"停止"和"运行中"两种状态间切换

---

### 页面 2：Providers（供应商管理）

#### 页面目的

管理所有 LLM Provider 配置（添加、编辑、删除、切换活跃 Provider）。

#### 信息层级

```
Providers
├── 顶部操作栏
│   ├── 页面标题 + 副标题
│   └── "添加 Provider" 按钮（右上角）
├── Provider 卡片网格
│   └── 每个 Provider 一张卡片
└── 底部："添加 Provider" 按钮（居中）
```

#### Provider 卡片需要展示的信息

- Provider 名称（如 "OpenAI Official"）（用户添加卡片可以不填，默认会使用url的关键词作名称）
- API Endpoint（url）
- api 提供的模型名称
- 可信度评分（右上角，大号数字 + %）
- I/C/O 各自的平均差异率（所有历史 所有模型）
- **活跃状态** — 当前正在审计的 Provider 需要特殊视觉标记
- 操作按钮（编辑、删除）

#### 交互需求

- **点击卡片** → 切换该 Provider 为活跃 Provider（Dashboard 数据随之切换）
- **点击"编辑"** → 弹出编辑表单（模态框或侧边栏）
- **点击"删除"** → 确认对话框
- **点击"添加 Provider"** → 弹出新建表单
- 点击任何一张卡片的任何一个模型，各个卡片的审计结果会切换成这个模型的审计结果，如果个别卡片（provider）不提供这个模型，就显示空

#### 表单字段（添加/编辑 Provider）

1. Provider 名称（文本输入）
2. API Endpoint（文本输入，如 `https://api.openai.com/v1/chat/completions`）
3. API Key（密码输入，可切换显示/隐藏）
4. 模型列表（多选或标签输入）
5. 是否设为活跃 Provider（开关）

#### 传达

1. i/c/o三种token 审计和声称的三组差异关系，率
2. 审计 和声称各自下input和cache （input+output=prefill）的比值关系

### 页面 3：Settings（设置）

#### 页面目的

配置应用偏好和开发者选项。

#### 设置项分类

```
Settings
├── 基础设置
│   ├── 代理端口（数字输入，默认 8080）
│   └── 界面语言（下拉选择：简体中文 / English）
├── 代理设置
│   ├── 自动配置 Claude（开关）
│   └── 启动时自动运行代理（开关）
└── 高级设置（可选）
    ├── 审计精度模式（快速/精确）
    └── 数据保留期限（天）
```

#### 交互需求

- 开关组件：开启/关闭状态有明确的视觉反馈
- 输入项：修改后自动保存（或提供"保存"按钮）
- 危险操作（如"清除所有审计数据"）需要确认对话框

## 四、全局交互模式

### 1. 侧边栏导航

- **行为**：点击导航项 → 主内容区切换到对应页面（带淡入动画）
- **状态**：当前活跃页面在侧边栏中有视觉强调（左侧竖线 + 背景色变化）
- **代理状态**：侧边栏底部有代理状态按钮
  - 绿色 + "代理运行中" = 代理正在运行
  - 灰色 + "启动代理" = 代理已停止
  - 点击可切换运行状态

### 2. 页面切换动画

- 新页面进入：淡入 + 轻微向上位移（Y: 8px → 0）
- 持续时间：250ms，缓动函数：cubic-bezier(0.16, 1, 0.3, 1)

### 3. 数据刷新

- Dashboard 应有"刷新"按钮（右上角）
- 刷新时图表有重新绘制动画（可选）

### 4. 响应式行为（初步）

- **桌面（>1024px）**：左右两栏布局（Dashboard）
- **平板（768-1024px）**：单栏，卡片堆叠
- **手机（<768px）**：侧边栏可折叠，主内容区全宽

## 五、数据可视化规范

### 1. Token 数量单位

- < 1K：显示完整数字（如 842）
- 1K - 999K：显示 K（如 12.4K）
- ≥ 1M：显示 M（如 1.2M）

### 2. 差异率颜色编码

- **绿色（#10B981 附近）**：差异率 < 5%，可信
- **黄色（#D97706 附近）**：差异率 5%-15%，需关注
- **红色（#DC2626 附近）**：差异率 > 15%，可疑

### 3. I/C/O 颜色编码（全局统一）

各自对应一种颜色

## 附录：关键术语表

| 术语                 | 含义                                               |
| -------------------- | -------------------------------------------------- |
| **审计 Token** | TokenAccountant 自己计算出的 Token 数（基准真相）  |
| **声明 Token** | Provider 在 API 响应中声称的 Token 数              |
| **差异率**     | (声明 Token - 审计 Token) / 审计 Token × 100%     |
| **可信度评分** | 基于历史差异率计算的综合评分（0-100%）             |
| **Session**    | 一次连续的审计记录周期（从用户启动代理开始）       |
| **I/C/O**      | Input Tokens / Cache Tokens / Output Tokens 的缩写 |
| **Provider**   | LLM API 供应商（如 OpenAI、Anthropic、DeepSeek）   |
